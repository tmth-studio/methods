Pyramid Principle: Guided Workbook

Workflow for strategic analysis and presentations. Copilot does the work. You check the work.

v3 — written in Simplified Technical English. Full Minto coverage: lint rules, MECE, vertical and horizontal logic, copy standards, chart selection, slide anatomy. Companion to Pyramid_Methods_Comprehensive_Final.docx.

How to use this workbook

Division of work. Copilot does the production work in each step: analysis, drafts, structure, and chart specification. You do three tasks only:

  1. Paste the step prompt into Copilot. Each step has a prepared prompt (purple box). Attach your inputs to the prompt.
  2. Check the output against the review checklist (amber box). Each check is a specific Minto rule.
  3. Write the approved output in the output box. The output is the input for the next step. Do not continue with an output that is not approved.

The gates are the method. The value of Minto is the test of each element before you build on it. If a check fails, Copilot must repair the work and send it again. A failed check never means "acceptable".

FLOW A: ANALYSIS Find the cause

Steps in Flow A

A1

Frame the problem

Identify the problem. Identify the decision that waits for the answer.

Input: raw problem statement (email, meeting note, briefing) · Output: problem frame in one sentence

Copilot procedure — do the steps in sequence

  1. Read the source material. Paste emails, briefing extracts, and meeting notes into the prompt.
  2. Find four elements. The symptom: the problem you can see. The evidence: numbers, timeframe, baseline. The decision: the choice that waits. The reader: the person who decides.
  3. Keep the symptom and the cause apart. "Churn increased" is a symptom. "The price is wrong" is a hypothesis. Do not put a hypothesis in the frame.
  4. Calculate the stakes. What does the problem cost each year? What is the cost of a wrong decision?
  5. Write one sentence: [symptom + size + timeframe]; we must identify [X] before [decision + cost].
  6. Show each missing element. Do not invent data.

Prompt for Copilot

You do Step A1 (Frame the Problem) of a Minto Pyramid analysis.

Source material: [PASTE emails / notes / briefing]

Do this:
1. Find: the symptom (observable, with numbers), the evidence (data,
   timeframe, baseline), the decision that waits (with cost), the reader
   (the person who decides).
2. Do NOT give a diagnosis. If the source gives causes, put them in a
   separate list: "candidate hypotheses for later". Keep them out of
   the frame.
3. Write a one-sentence problem frame:
   "[Symptom + size + timeframe]; we must identify [X] before
   [decision + cost]."
4. List each item that is missing. I will supply it. Do not invent data.

Output: the frame sentence, the four elements in a table, the missing
items.

Your review checklist

  • ✓ The symptom is observable and has numbers. It is not an interpretation.
  • ✓ The frame has no diagnosis. The word "because" is a fail.
  • ✓ The decision and its cost are in the frame.
  • ✓ The reader has a name.
  • ✓ Each flagged gap is a true gap. Supply the data or accept the limit.

Reference example

Good: "SME churn has risen from 22% to 35% over three years (£6M annual revenue impact); we need to identify the root cause before committing £2M to the product roadmap."

Bad: "We have a churn problem because our prices are too high." (This has a diagnosis, no decision, and no stakes.)

GATE: the frame is one sentence. It has only the symptom. It names the decision and the reader.

Next: A2 — Write the Situation and the Complication
A2

Write the Situation and the Complication

Write the baseline that all persons accept. Then identify what changed.

Input: problem frame (A1) + available data · Output: Situation statement, Complication statement, evidence register

Copilot procedure — do the steps in sequence

  1. Collect the baseline facts from the sources: segment size, revenue, historical metrics, market context, and the items that did not change.
  2. Sort each fact into two groups. Group 1: not controversial — the reader accepts it without proof. Group 2: contested — it needs evidence. Only Group 1 can go into the Situation.
  3. Write the Situation. Use 2 to 4 sentences. Use facts only. Do not use "but" or "however". Do not use judgment words (failing, weak, poor).
  4. Identify the change. What is different now? When did it start? What broke as a result?
  5. Write the Complication. Start with "But". Name the change and the damage, with numbers. Do not give a solution. Do not give a cause.
  6. Make the evidence register. It is a table with two columns: fact | source. Include each fact you used.
  7. Do the Nod Test on both statements. For each sentence, ask: will the named reader agree without proof? Mark each sentence that fails.

Prompt for Copilot

   facts that are not controversial can go into the Situation.

   no judgment words. Each claim must point to the data supplied.
3. Write the Complication (2–3 sentences): start with "But", name the

Your review checklist

  • ✓ Each Situation sentence passes the Nod Test. The reader will not object.
  • ✓ The Situation has zero interpretation. Adjectives such as "strong" or "weak" are a fail.
  • ✓ The Complication follows from the Situation. The reader feels the tension.
  • ✓ The Complication has no solution and no cause claim.
  • ✓ Each number in the register has a source. You can show the source in the meeting.

Reference example (Fairy Food Mother)

Situation: "Prosus acquired JET with a mandate to replicate the iFood playbook. JET holds ~45% UK market share. Young families are 45% of the base. The business is repositioning around profitability."

Complication: "But young families sit at 42% 90-day retention despite the highest promotional spend of any segment. They respond to deals, then leave."

Note the shape. The Situation makes the Complication painful. A profit mandate plus margin spent on a segment that does not stay = tension. The reader feels this before you speak about solutions.

GATE: both statements pass the Nod Test. Each fact has a source.

Next: A3 — Make hypotheses and test them
A3

Make hypotheses and test them

List the possible causes. Write what each cause predicts. Test the predictions against the data.

Input: Situation + Complication + evidence register (A2) · Output: hypothesis table with verdicts, strongest hypothesis, research gaps

Copilot procedure — do the steps in sequence

  1. Write 3 to 5 candidate hypotheses for the cause. Include the explanation that the stakeholders already believe. You must test it, not assume it.
  2. Check that the set is MECE. The hypotheses must not overlap. Two phrasings of one cause are one hypothesis. The set must also cover the space. Ask: "what other cause is possible?"
  3. For each hypothesis, write predictions: "If H is true, the data will show X, Y, Z." Each prediction must be testable with data you have or can get.
  4. Also write negative predictions: "If H is true, we will NOT see W." If you cannot write a negative prediction, the hypothesis is not testable.
  5. Test each prediction against the evidence register and other supplied data. Record evidence FOR and evidence AGAINST. Do not give a verdict from friendly evidence alone.
  6. Give verdicts: SUPPORTED / CONTRADICTED / INCONCLUSIVE. A SUPPORTED verdict needs at least one negative prediction that survived the test.
  7. List the research gaps. Which one missing data item will change the verdict most? That item is the most valuable next research action.

Prompt for Copilot

You do Step A3 (Hypothesis Tests) of a Minto analysis.

Situation: [PASTE]
Complication: [PASTE]

   that the stakeholders already believe.

   shows X") AND negative predictions ("if true, we will NOT see W").
3. Test each prediction against the data. Record evidence FOR and
   evidence AGAINST.

Your review checklist

  • ✓ The stakeholders' explanation is in the table. It got a real test.
  • ✓ The hypotheses are MECE. No two are one cause with different words. No possible cause is missing.
  • ✓ Each SUPPORTED verdict survived a negative prediction test. Friendly evidence alone is not sufficient.
  • ✓ The "evidence against" column has content. An empty column shows that Copilot did not look.
  • ✓ The named research gap is worth its cost. If not, accept the uncertainty and record it.

Reference example (SME banking)

"Competitor pricing" was the belief of the CFO. Test: if price is the cause, current customers will leave and price objections will increase. Data: current customer churn was stable, and objections DECREASED 30%. Verdict: CONTRADICTED. One hypothesis survived — the competitor's messages changed the market's view. Its negative test also passed: current customers, who have not seen the messages at renewal, show no effect.

GATE: each verdict uses evidence FOR and AGAINST. The popular explanation got a test.

Next: A4 — Write the Question and the Answer
A4

Write the Question and the Answer

Write the real problem as one question. Answer it from the evidence.

Input: hypothesis verdicts (A3) · Output: the Question (one sentence), the Answer (one sentence)

Copilot procedure — do the steps in sequence

  1. Read the Situation, the Complication, and the strongest hypothesis together. The Question is what the reader asks when the reader knows all three.
  2. Write the Question. Test it three times. (a) It is ONE question. (b) You can answer it with what you know or can decide. (c) The answer tells you what to do. If the answer does not tell you the next move, the question is wrong.
  3. Check the level of the Question. It must sit ABOVE the surface debate. In the SME case, the surface question was "must we cut the price?" The real question was "how do we compete when the market has a new frame that we do not win on?"
  4. Write the Answer in one sentence. Use only the hypothesis that survived. The Answer is a claim about what is true or what to do. It is not a summary of findings.
  5. Check the chain: Answer ← strongest hypothesis ← evidence that survived. If a link needs new facts that are not in the register, flag it.

Prompt for Copilot

Strongest hypothesis + evidence: [PASTE from A3]

1. Write THE question that the reader asks when the reader knows the

   survived and its evidence.

Your review checklist

  • ✓ One question. No "and" that connects two decisions.
  • ✓ The answer sets the action. Apply the test: "when we answer this, we know what to do".
  • ✓ It is the real question, not the surface debate.
  • ✓ The Answer follows from the A3 verdicts. You can speak the chain aloud.

GATE: one question. The answer sets the action. The chain to the evidence is complete.

Next: A5 — Write the recommendation
A5

Write the recommendation

Change the answer into an action with costs, dates, and tests

Input: Question + Answer (A4) · Output: recommendation with resources, timeline, alternatives, success metrics

Copilot procedure — do the steps in sequence

  1. Write 3 to 4 real options for the Answer. Include "do nothing" as an honest baseline with its cost. Do not make it a weak option on purpose.
  2. Score each option against five criteria: strategic fit (does it use what the evidence says we win on?), cost, time to impact, reversibility, and risk if the analysis is wrong.
  3. Select one option. Write the recommendation: what, why (one clause that points to the Answer), resources, timeline, owner.
  4. Attach success metrics: 3 to 4 measures. Each measure has a baseline, a target, and a measurement date. A metric without a date is not a metric.
  5. Attach a decision gate: the condition to stop or review. Example: "if X has not moved by [date], review before more spend". The gate makes the recommendation safe to approve.
  6. Name the key assumption: the one item that, if false, makes the recommendation invalid.

Prompt for Copilot

You do Step A5 (Recommendation) of a Minto analysis.

Question: [PASTE]  Answer: [PASTE]
Constraints: budget [X], timeline [Y], strategic context [Z]

Do this:
1. Write 3–4 real options. Include "do nothing" with its real cost.
2. Score each option: strategic fit / cost / time to impact /
   reversibility / risk if wrong. Use a short table.
3. Recommend one option. Format: what, why (point to the Answer),
   resources, timeline, owner.
4. Success metrics: 3–4. Each has a baseline, a target, and a
   measurement DATE.
5. Decision gate: the stop/review condition and its date.
6. Key assumption: the one item that, if false, makes this invalid.

Output: options table, recommendation, metrics, gate, assumption.

Your review checklist

  • ✓ The alternatives are real. You could defend each one.
  • ✓ "Do nothing" has an honest cost.
  • ✓ Each metric has a baseline, a target, and a date.
  • ✓ The decision gate makes the recommendation safe for a careful CFO.
  • ✓ The key assumption carries real load. Test: if it is false, do you still act?

GATE: the recommendation stands on evidence. It has costs, a gate, and a named assumption.

B2

Frame the audience

The reader's beliefs set the start point of the argument

Input: format (B1) + reader knowledge · Output: reader profile: beliefs, decision, skeptics, presence

Copilot procedure — do the steps in sequence

  1. Write the profile of the decision-maker. Role. What the reader knows: this sets what the Situation can assume. What the reader believes about the cause: this sets what you must remove. What the reader cares about most: this sets the first argument.
  2. Map the room. Who attends? Who is skeptical, and about what? Who has influence on the decision-maker?
  3. Confirm the presence type. Live pitch: speak the SCQA, slides carry the exhibits. Document without a speaker: write the SCQA in full, the document stands alone.
  4. Write the belief gap: "The reader believes [X]. The argument must move the reader to [Y]." The pyramid exists to close this gap.

Next: B3 — Write the SCQA and the Governing Thought
B3

Write the SCQA and the Governing Thought

The opening that gets the reader's attention before you give proof

Input: reader profile (B2) + Situation/Complication (A2 if available) · Output: SCQA + Governing Thought + tone order

Copilot procedure — do the steps in sequence

  1. Write the Situation FROM THE READER'S KNOWLEDGE (the "knows" list from B2). It can differ from the analysis Situation. Include only what this reader accepts.
  2. Write the Complication so that it makes tension against what this reader cares about most.
  3. Write the Question that the reader now asks. Your recommendation must answer this exact question. If it does not, the SCQA or the recommendation is wrong.
  4. Write the Governing Thought in three drafts:
    • Draft 1: write what you want to happen (usually a WHAT).
    • Draft 2: add what it produces (the SO-WHAT: revenue, retention, cost, position).
    • Draft 3: compress to 25 words or fewer. Active voice. Start with a verb.
  5. Select the tone order. S-C-A: standard, builds tension. A-S-C: direct, the answer first, for impatient senior readers. C-S-A: alarm first, for urgent cases. Give the reason from the reader profile.
  6. Do the full Nod Test. For each element, write the reader's expected internal response. All four responses must be agreement.

Your review checklist — the full Nod Test

  • ✓ Situation → the reader thinks "yes, that is where we are". Not "who says?"
  • ✓ Complication → the reader thinks "yes, that is a real problem". Not "is it?"
  • ✓ Question → the reader thinks "yes, that is my exact question now".
  • ✓ Answer → the reader thinks "if that is true, my question is closed". Belief comes later. That is the pyramid's task.
  • ✓ Governing Thought: 25 words or fewer. Starts with a verb. States what it PRODUCES. Can be proven false.
  • ✓ The tone order fits the reader. For a senior, impatient reader: examine A-S-C.

Governing Thought: three-draft example (FFM)

Draft 1 (WHAT): "We should build an AI food assistant for families."

Draft 2 (better, too long): "We should launch Fairy Food Mother, an AI-powered food assistant that drives habit over discount dependency, converts 20% of Segment B, and generates £3.9M..."

Draft 3 (≤25 words, SO-WHAT): "Launch Fairy Food Mother: a family food assistant converting young families from discount-dependent to habit-driven, generating £3.9M annual revenue at 60%+ retention."

GATE: four agreements. The Governing Thought is ≤25 words, starts with a verb, states the SO-WHAT.

Next: B4 — Build the pyramid
B4

Build the pyramid

Key-lines and sub-points, tested for vertical logic, horizontal logic, MECE, and order

Input: Governing Thought (B3) + evidence register (A2/A3) · Output: tested pyramid: 3–5 key-lines, each with 3–5 sub-points

Copilot procedure — do the steps in sequence

  1. Ask about the Governing Thought: "Why is this true?" For an action: "Why must we do this?" The answers are candidate key-lines. Use the format pattern from B1 (example: Desirable / Feasible / Viable).
  2. Select the logic type. Keep it constant in each group:
    • Inductive (usual for recommendations): parallel independent reasons. Each reason matters alone. Test each pair: "are these the same KIND of idea?"
    • Deductive (for logic chains): premise → premise → conclusion. Test: does the conclusion need both premises? Do not mix deductive and inductive in one group.
  3. Do the MECE test on the key-line set:
    • Mutually exclusive: no two key-lines are one argument with different words. "Improve retention" and "reduce churn" are one argument two times. Test: can one exhibit prove both? If yes, merge them.
    • Collectively exhaustive: nothing the reader needs is absent. Test: "if all key-lines are true, MUST the reader accept the Governing Thought?" If the reader can accept all and refuse, an argument is missing.
  4. Select ONE order and write it: time (first to last), structure (by part), or degree (most important first). Recommendations usually take degree order.
  5. Under each key-line, put 3 to 5 sub-points from the evidence register. Test the vertical logic at each joint. The sub-points must ANSWER the question the key-line causes ("why?" / "how?"). The key-line must give a summary of the sub-points, not an introduction to them.
  6. Remove orphans. A sub-point that does not support its key-line must move or go. Flag each claim without evidence for B6 (exhibit needed) or remove it.
  7. Write the audit result: MECE result, selected order, logic type for each group, vertical logic check for each key-line.

   true?" Follow the format pattern.

   (b) If all key-lines are true, MUST the reader accept the Governing
   Thought? If not, name the missing argument.

Your review checklist

  • ✓ Vertical logic: read each key-line. Ask "why?". Read its sub-points. Do they answer in full?
  • ✓ Summary test: you can rebuild each key-line from its sub-points alone.
  • ✓ MECE: no overlap (the one-exhibit test). No gap (the if-all-true test).
  • ✓ One order, written, and it serves the reader. Degree order for busy executives.
  • ✓ Same kind: all key-lines are arguments. Not a mix of argument, evidence, and plan.
  • ✓ No orphan sub-points. Each claim has evidence below it, or a flag for B6.

Vertical logic example

Key-line: "Churn is perception-driven, not price-driven." The reader asks: "why do you say that?" The sub-points must answer that exact question: (a) current customers are stable — price pain hits them first; (b) price objections decreased 30%; (c) all 10 lost deals name the competitor; (d) deal sizes are stable — buyers accept the current price. Each sub-point answers the "why". That is vertical logic in good condition.

GATE: vertical logic is good at each joint. MECE passes both tests. One order.

Next: B5 — Attack the argument
B5

Attack the argument

Attack each key-line with the room's real skeptics before they do

Input: pyramid (B4) + skeptic map (B2) + failed hypotheses (A3) · Output: objection matrix, repairs applied, revised ask

Copilot procedure — do the steps in sequence

  1. For each key-line, write the strongest objection. Write it in the voice of the NAMED skeptic from B2. Do not use a generic critic.
  2. Write the counter for each objection. A counter must point to evidence in the register. A counter that is only a louder claim fails.
  3. Give each counter a class. HOLDS: the evidence exists. NEEDS EVIDENCE: the evidence is available — add it to the B6 list. CONCEDE AND REFRAME: the objection is correct — revise the pyramid now. Do not defend a bad position.
  4. Find the argument with the least evidence in the pyramid. Decide: make it stronger, or make its role smaller. A weak defence argument can become context instead of a pillar.
  5. Use the failed hypotheses from A3 in attack. The reader's belief got a test and failed. Plan where that lands in the flow. Usually early, to clear the ground.
  6. Revise the ask if the attack showed risk. Put the decision gate inside the ask: "approve X; gate at 90 days on metric Y". An ask with a gate is easier to approve.

   NAMED SKEPTIC. No generic objections.

   counters that are only claims.

  • ✓ The objections sound like your real room, not a textbook.
  • ✓ Each HOLDS counter points to evidence you can show in the meeting.
  • ✓ Each CONCEDE item changed the pyramid. Check that the B4 output changed.
  • ✓ The weakest argument is now stronger or smaller. It does not carry load.
  • ✓ The ask now contains its own decision gate.

Next: B6 — Design the exhibits
B6

Design the exhibits

Write the message first. Select the chart second.

Input: revised pyramid (B5) + evidence register · Output: exhibit specification sheet, one specification for each exhibit

Primary rule: the message selects the chart

Do not start from the data. Do not ask "which chart fits these numbers?" Start from the claim. Ask "what must this exhibit prove?" Then select the one chart form that shows that comparison. If you cannot write the claim as a title, do not build the exhibit.

Copilot procedure — do the steps in sequence, for each exhibit

  1. Write the assertion title first. Take the sub-point. Write the title as a full sentence that contains the claim and the result. Fix this title BEFORE you select a chart.
    • Label: "Q4 lost-deal analysis"
    • Assertion: "All 10 Q4 lost deals cite the competitor — none cite price"
  2. Identify the comparison type. Each quantitative message is one of five types. The type sets the chart family:
    Comparison typeMessage keywordsChart form
    Component (part of a total)"share of", "percentage of", "X% of total"Pie (5 parts maximum) or 100% stacked bar
    Item (rank of items)"larger than", "ranked", "more than", "less than"Horizontal bar
    Time series (change across time)"grew", "decreased", "since", "trend"Column (few periods) or line (many periods)
    Frequency (distribution)"concentration", "range", "most are between"Histogram / column
    Correlation (relation)"relates to", "increases with", "depends on"Scatter or paired horizontal bar
  3. One message for each exhibit. If the title has "and" between two claims, make two exhibits. A chart that proves two things proves nothing well.
  4. Select the evidence type when the claim is not quantitative. Quote strip: exact customer or analyst quotes with names. Comparison table: us against them, on named dimensions. Mockup: for product propositions. Mechanism diagram: for processes and loops. Scenario table: for financial cases — always pessimistic / central / optimistic, never one point value.
  5. Set the highlight. Each exhibit has one visual emphasis that matches the title claim: one bar with a different colour, one circle around the divergence, one row in bold. If all items have emphasis, no item has emphasis.
  6. Remove the decoration. No 3D. No background fills. No legend when direct labels fit. No grid clutter. Round the numbers to the message (£3.9M, not £3,912,447). Start the axis at zero. If the deviation is the message, show the axis break and say so.
  7. Add the source and the units to each exhibit: "Source: CRM lost-deal records, Oct–Dec 2025. n=10." An exhibit without a source is a story.
  8. Write the specification row for each exhibit: ID, sub-point served, assertion title, comparison type, chart form, data needed, highlight, source, status (data ready / to collect).

Next: B7 — Write the narrative
B7

Write the narrative

SCQA introduction, body by key-line, Minto conclusion — under full copy standards

Input: pyramid (B5) + exhibit specifications (B6) + SCQA (B3) · Output: complete narrative + speaker notes

Copilot procedure — do the steps in sequence

  1. Write the introduction as the SCQA in the selected tone order. The reader must be able to read it in 30 seconds. It ends with the Governing Thought.
  2. After the Governing Thought, show the key-lines in one sentence. Example: "Three things make this the right move: it is desirable, deliverable and defensible."
  3. Write the body. One section for each key-line, in the pyramid order. Section pattern: heading = the key-line claim → why it matters (2–3 sentences) → the evidence, with the exhibits named by their assertion titles → transition that plants the next key-line's question.
  4. Write the conclusion in Minto's three parts. No other structure is acceptable:
    • State the Governing Thought again (new words, same claim).
    • Name the key assumption: "This rests on [assumption]; if [signal], we review at [gate]." A named assumption stops the skeptic who waited to name it.
    • Next action: who does what, and the start date.
  5. Apply the copy standards below to each sentence. Apply them as mechanical checks, not as taste.
  6. Keep the speaker notes separate from the narrative: details, statistics, and story colour that help the speaker but load the page.

Copy standards for the deliverable — apply as mechanical checks (Minto Part 12)

  1. Active voice. The subject acts. "We will reposition", not "repositioning will be undertaken".
  2. Remove hidden verbs. Words with -tion/-ment/-ance that hide a verb: "utilisation of" → "use"; "implementation of X requires" → "to implement X, we must".
  3. 25 words maximum for each sentence. Count the words. Break at the subordinate clause.
  4. One idea for each sentence. An "and" between two claims = two sentences.
  5. Numbers: spell one to nine; use numerals from 10; dates as 8 May 2026; each % has a referent ("35% of SME accounts", never a bare "35%").
  6. Punctuation: no exclamation marks; no Oxford comma; em dashes with spaces, and few.
  7. Capitals: proper nouns only. "the chief financial officer", "the repositioning campaign".
  8. No empty hedges. "It could be argued that" = remove. Make the argument or remove it.

Next: B8 — Do the lint check
B8

Do the lint check

Sixteen rules and six diagnostics. Do this inspection before you build slides or send the document.

Input: all products so far · Output: lint report — each rule PASS or repaired

The 16 lint rules

  1. The Governing Thought is 25 words or fewer, active voice, verb first
  2. The Governing Thought states a SO-WHAT (what it produces), not a WHAT
  3. The SCQA contains exactly one Question
  4. The Situation contains no contested claim and no "but/however"
  5. Each heading and slide title is a full-sentence claim — testable, can be false
  6. 3 to 5 key-lines, no more
  7. The key-lines are MECE (one-exhibit overlap test; if-all-true gap test)
  8. Each key-line is a summary of its sub-points (you can rebuild it from below)
  9. Each group is fully inductive or fully deductive — never mixed
  10. Each group follows ONE written order: time, structure or degree
  11. No orphan claims — each claim has evidence below it
  12. Each exhibit title is a claim, not a label
  13. One message for each exhibit; each exhibit has a source and units
  14. Sentences have 25 words maximum, active voice, no hidden verbs
  15. Number format: one to nine spelled, numerals from 10, dates as 8 May 2026, each % has a referent
  16. The conclusion states the Governing Thought again + names the key assumption + gives the next action

The 6-check final diagnostic

  1. Title-read test: read ONLY the headings and slide titles in sequence. Does the full argument stand with nothing else?
  2. Nod test: does the SCQA still get four agreements from the named reader?
  3. So-what test: ask "so what?" for each section and slide. Remove each item without an answer.
  4. Skeptic pass: each named skeptic's objection has a counter with evidence, in position in the flow.
  5. Evidence chain: each number points to the register. You can show each register source in the meeting.
  6. Single ask: the document asks for exactly one decision, with a gate, an owner and a date.

Pyramid Workbook A — Analysis

Flow A: find the cause. Copilot does the work. You check the work.

v4 — split edition, Simplified Technical English. This document is Flow A only: frame, situation and complication, hypotheses, evidence sweep, question and answer, recommendation, hand-off. Companion: Pyramid_Workbook_B_Presentation.html (Flow B — make the case).

How to use this workbook

Division of work. Copilot does the production work in each step: analysis, drafts, structure, and chart specification. You do three tasks only:

  1. Paste the session state header, then the step prompt, into Copilot. Each step has a prepared prompt (purple box). The state header (below) tells Copilot what is already done. Attach your inputs.
  2. Check the output against the review checklist (amber box). Each check is a specific Minto rule.
  3. Write the approved output in the output box. The output is the input for the next step. Do not continue with an output that is not approved.

The gates are the method. The value of Minto is the test of each element before you build on it. If a check fails, Copilot must repair the work and send it again. A failed check never means "acceptable".

Two layers. This workbook is the thinking layer: you fill it conversationally with an assistant, step by step, and a half-finished workbook is a legitimate state — park it and come back. The Python generators in the same repository (run_pyramid_analysis.py, generate_pyramid_memo.py, generate_presentation_deck.py, generate_standalone_deck.py) are the output layer: attach one to a code-interpreter assistant, move the approved content into its DATA section, and it builds the .docx or .pptx deterministically, with self-checks that refuse to build on rule failures.

Session state header — paste at the top of every prompt

Copilot has no memory of your process. Without this header, it repeats completed work, proposes steps you have done, and does not ask for the information that would improve the output. Fill the brackets and paste this block above each step prompt:

SESSION STATE
Completed steps: [example: A1-A3]
Current step: [example: A4]
Approved outputs attached below: [list them]

Rules for this session:
1. Do not repeat or redo work from the completed steps. Their outputs
   are final unless I ask for a change.
2. Do not propose next steps or a plan. The workbook sets the
   sequence. Do only the current step.
3. BEFORE you produce the output: if information is missing that
   would make the output materially better, ask me numbered
   questions first and stop. If you have enough, say "no questions"
   and produce the output.
4. If an instruction in this prompt conflicts with something you
   assume, follow the prompt and flag the conflict.

Rule 3 is the important one. It changes Copilot from a passive producer into an active interviewer: it must ask for the missing budget figure, the missing attendee name, or the missing data source before it writes — instead of inventing around the gap.

Verification protocol — three checks catch the errors. Use all three.

1. Self-check — same chat. Add this line to the end of each prompt in this workbook:

Before you give the output: test your work against each rule in this
prompt. Add a table at the end: rule | PASS or FAIL | repair made.
Repair each FAIL before you give the output.

2. Independent check — new chat. The producer must not be the only checker of its own work. For the heavy gates (A3 hypotheses, A4 evidence sweep, A6 recommendation), open a NEW Copilot chat with no history. Paste this verifier prompt, with the output and the step's checklist:

You are a verifier. You did not make this work. Your task is to find
defects. Do not repair them.

Work product: [PASTE the output]
Rules: [PASTE the step's review checklist and gate]

Do this:
1. Test the product against each rule. Try to make each rule fail.
2. Quote the exact text of each failure.
3. Do not accept a claim without evidence inside the product.
4. Output a table: rule | PASS or FAIL | exact quote | proposed repair.
5. End with one verdict: ACCEPT or RETURN FOR REPAIR.

3. Human checks — only you can do these. Copilot cannot see the rendered page, and it cannot know if your data is true. You must check: five numbers against the evidence register, that each register source is a document you can show, and that no GAP_OPEN row survived the sweep.

FLOW A: ANALYSIS Find the cause

Steps in Flow A

  1. Frame the problem
  2. Write the Situation and the Complication
  3. Make hypotheses and test them
  4. Sweep the evidence (adversarial)
  5. Write the Question and the Answer
  6. Write the recommendation
  7. Give the results to Document B
A1

Frame the problem

Identify the problem. Identify the decision that waits for the answer.

Input: raw problem statement (email, meeting note, briefing) · Output: problem frame in one sentence

Copilot procedure — do the steps in sequence

  1. Read the source material. Paste emails, briefing extracts, and meeting notes into the prompt.
  2. Find four elements. The symptom: the problem you can see. The evidence: numbers, timeframe, baseline. The decision: the choice that waits. The reader: the person who decides.
  3. Keep the symptom and the cause apart. "Churn increased" is a symptom. "The price is wrong" is a hypothesis. Do not put a hypothesis in the frame.
  4. Calculate the stakes. What does the problem cost each year? What is the cost of a wrong decision?
  5. Write one sentence: [symptom + size + timeframe]; we must identify [X] before [decision + cost].
  6. Show each missing element. Do not invent data.

Prompt for Copilot

You do Step A1 (Frame the Problem) of a Minto Pyramid analysis.

Source material: [PASTE emails / notes / briefing]

Do this:
1. Find: the symptom (observable, with numbers), the evidence (data,
   timeframe, baseline), the decision that waits (with cost), the reader
   (the person who decides).
2. Do NOT give a diagnosis. If the source gives causes, put them in a
   separate list: "candidate hypotheses for later". Keep them out of
   the frame.
3. Write a one-sentence problem frame:
   "[Symptom + size + timeframe]; we must identify [X] before
   [decision + cost]."
4. List each item that is missing. I will supply it. Do not invent data.

Output: the frame sentence, the four elements in a table, the missing
items.

Your review checklist

  • ✓ The symptom is observable and has numbers. It is not an interpretation.
  • ✓ The frame has no diagnosis. The word "because" is a fail.
  • ✓ The decision and its cost are in the frame.
  • ✓ The reader has a name.
  • ✓ Each flagged gap is a true gap. Supply the data or accept the limit.

Reference example

Good: "SME churn has risen from 22% to 35% over three years (£6M annual revenue impact); we need to identify the root cause before committing £2M to the product roadmap."

Bad: "We have a churn problem because our prices are too high." (This has a diagnosis, no decision, and no stakes.)

GATE: the frame is one sentence. It has only the symptom. It names the decision and the reader.

Next: A2 — Write the Situation and the Complication
A2

Write the Situation and the Complication

Write the baseline that all persons accept. Then identify what changed.

Input: problem frame (A1) + available data · Output: Situation statement, Complication statement, evidence register

Copilot procedure — do the steps in sequence

  1. Collect the baseline facts from the sources: segment size, revenue, historical metrics, market context, and the items that did not change.
  2. Sort each fact into two groups. Group 1: not controversial — the reader accepts it without proof. Group 2: contested — it needs evidence. Only Group 1 can go into the Situation.
  3. Write the Situation. Use 2 to 4 sentences. Use facts only. Do not use "but" or "however". Do not use judgment words (failing, weak, poor).
  4. Identify the change. What is different now? When did it start? What broke as a result?
  5. Write the Complication. Start with "But". Name the change and the damage, with numbers. Do not give a solution. Do not give a cause.
  6. Make the evidence register. It is a table with two columns: fact | source. Include each fact you used.
  7. Do the Nod Test on both statements. For each sentence, ask: will the named reader agree without proof? Mark each sentence that fails.

Prompt for Copilot

You do Step A2 (Situation and Complication) of a Minto analysis.

Problem frame: [PASTE from A1]
Available data: [PASTE data / attach files]

Do this:
1. Sort all facts into two groups: not controversial / contested. Only
   facts that are not controversial can go into the Situation.
2. Write the Situation (2–4 sentences): facts only, no "but/however",
   no judgment words. Each claim must point to the data supplied.
3. Write the Complication (2–3 sentences): start with "But", name the
   change and the damage, with numbers. NO solution. NO diagnosis.
4. Make the evidence register: fact | source | date.
5. Do the Nod Test: for each sentence, say if [READER] will agree
   without proof. Flag each failure and give a repair.

Output: Situation, Complication, evidence register, Nod Test results.

Your review checklist

  • ✓ Each Situation sentence passes the Nod Test. The reader will not object.
  • ✓ The Situation has zero interpretation. Adjectives such as "strong" or "weak" are a fail.
  • ✓ The Complication follows from the Situation. The reader feels the tension.
  • ✓ The Complication has no solution and no cause claim.
  • ✓ Each number in the register has a source. You can show the source in the meeting.

Reference example (Fairy Food Mother)

Situation: "Prosus acquired JET with a mandate to replicate the iFood playbook. JET holds ~45% UK market share. Young families are 45% of the base. The business is repositioning around profitability."

Complication: "But young families sit at 42% 90-day retention despite the highest promotional spend of any segment. They respond to deals, then leave."

Note the shape. The Situation makes the Complication painful. A profit mandate plus margin spent on a segment that does not stay = tension. The reader feels this before you speak about solutions.

GATE: both statements pass the Nod Test. Each fact has a source.

Next: A3 — Make hypotheses and test them
A3

Make hypotheses and test them

List the possible causes. Write what each cause predicts. Test the predictions against the data.

Input: Situation + Complication + evidence register (A2) · Output: hypothesis table with verdicts, strongest hypothesis, research gaps

Copilot procedure — do the steps in sequence

  1. Write 3 to 5 candidate hypotheses for the cause. Include the explanation that the stakeholders already believe. You must test it, not assume it.
  2. Check that the set is MECE. The hypotheses must not overlap. Two phrasings of one cause are one hypothesis. The set must also cover the space. Ask: "what other cause is possible?"
  3. For each hypothesis, write predictions: "If H is true, the data will show X, Y, Z." Each prediction must be testable with data you have or can get.
  4. Also write negative predictions: "If H is true, we will NOT see W." If you cannot write a negative prediction, the hypothesis is not testable.
  5. Test each prediction against the evidence register and other supplied data. Record evidence FOR and evidence AGAINST. Do not give a verdict from friendly evidence alone.
  6. Give verdicts: SUPPORTED / CONTRADICTED / INCONCLUSIVE. A SUPPORTED verdict needs at least one negative prediction that survived the test.
  7. List the research gaps. Which one missing data item will change the verdict most? That item is the most valuable next research action.

Prompt for Copilot

You do Step A3 (Hypothesis Tests) of a Minto analysis.

Situation: [PASTE]
Complication: [PASTE]
Evidence register: [PASTE]
Additional data: [PASTE / attach]

Do this:
1. Write 3–5 MECE hypotheses for the cause. Include the explanation
   that the stakeholders already believe.
2. For each hypothesis: write positive predictions ("if true, the data
   shows X") AND negative predictions ("if true, we will NOT see W").
3. Test each prediction against the data. Record evidence FOR and
   evidence AGAINST.
4. Verdicts: SUPPORTED (needs one negative prediction that survived) /
   CONTRADICTED / INCONCLUSIVE.
5. Output a table: Hypothesis | Predictions | Evidence for | Evidence
   against | Verdict.
6. Name the strongest hypothesis. Name the one missing data item that
   will change your confidence most.

Your review checklist

  • ✓ The stakeholders' explanation is in the table. It got a real test.
  • ✓ The hypotheses are MECE. No two are one cause with different words. No possible cause is missing.
  • ✓ Each SUPPORTED verdict survived a negative prediction test. Friendly evidence alone is not sufficient.
  • ✓ The "evidence against" column has content. An empty column shows that Copilot did not look.
  • ✓ The named research gap is worth its cost. If not, accept the uncertainty and record it.

Reference example (SME banking)

"Competitor pricing" was the belief of the CFO. Test: if price is the cause, current customers will leave and price objections will increase. Data: current customer churn was stable, and objections DECREASED 30%. Verdict: CONTRADICTED. One hypothesis survived — the competitor's messages changed the market's view. Its negative test also passed: current customers, who have not seen the messages at renewal, show no effect.

GATE: each verdict uses evidence FOR and AGAINST. The popular explanation got a test.

Next: A4 — Sweep the evidence (adversarial)
A4

Sweep the evidence (adversarial)

The hypotheses are tested. Before the answer is written, every claim that will carry weight gets an adversarial evidence pass.

Input: hypothesis verdicts (A3) + source materials · Output: evidence register — one row per claim, status marked

Friendly evidence alone is never sufficient

The sweep hunts for disconfirming evidence and records the hunt even when it finds nothing. An unrecorded search is indistinguishable from no search.

Copilot procedure — do the steps in sequence

  1. Attach the engagement's source materials: data extracts, reports, interview notes, prior analyses.
  2. List every claim that will carry weight: the surviving hypothesis, the emerging answer, and each load-bearing supporting fact.
  3. For EVERY claim: find the best supporting evidence and cite the source.
  4. For EVERY claim: actively search for disconfirming evidence — record what was looked for AND what was found, even when nothing was found.
  5. Mark each claim's status honestly: EVIDENCED / GAP_RISK_ACCEPTED (with a stated reason) / GAP_OPEN.
  6. A GAP_OPEN row blocks the hand-off — resolve it, or accept the risk with a reason a sceptic could read.

Prompt for Copilot

You do Step A4 (Evidence Sweep) of a Minto analysis.

Source materials: [ATTACH data extracts, reports, interview
notes, prior analyses]
Claims under test: [PASTE the A3 verdicts and the emerging answer]

Attach the engagement's source materials. For EVERY claim in the
analysis:
1. Find the best supporting evidence and cite the source.
2. Actively search for DISCONFIRMING evidence and record what you
   looked for and what you found — even when nothing was found.
3. Mark the status honestly: EVIDENCED, GAP_RISK_ACCEPTED with a
   stated reason, or GAP_OPEN.

Output the register as a table: claim | best supporting evidence |
source | counter-evidence search (looked for / found) | status.

Do not invent evidence. Do not silently drop a claim you cannot
evidence.

Your review checklist

  • ✓ Every claim has a row.
  • ✓ Every row records a counter-evidence search, not just friendly support.
  • ✓ No GAP_OPEN rows remain at hand-off.
  • ✓ Every GAP_RISK_ACCEPTED has a reason a sceptic could read.
  • ✓ The sources are showable in the meeting.

⚠ Engagement asset — keep out of the public repository

  • The filled register lives in the client tenant. Never commit a filled register to the public repository.
  • The register maps field-for-field onto the EVIDENCE_REGISTER structure in run_pyramid_analysis.py and generate_pyramid_memo.py — the generators refuse to build while any row is GAP_OPEN.

GATE: every claim has a row. Every row records a counter-evidence search. No GAP_OPEN rows remain.

Next: A5 — Write the Question and the Answer
A5

Write the Question and the Answer

Write the real problem as one question. Answer it from the evidence.

Input: hypothesis verdicts (A3) · Output: the Question (one sentence), the Answer (one sentence)

Copilot procedure — do the steps in sequence

  1. Read the Situation, the Complication, and the strongest hypothesis together. The Question is what the reader asks when the reader knows all three.
  2. Write the Question. Test it three times. (a) It is ONE question. (b) You can answer it with what you know or can decide. (c) The answer tells you what to do. If the answer does not tell you the next move, the question is wrong.
  3. Check the level of the Question. It must sit ABOVE the surface debate. In the SME case, the surface question was "must we cut the price?" The real question was "how do we compete when the market has a new frame that we do not win on?"
  4. Write the Answer in one sentence. Use only the hypothesis that survived. The Answer is a claim about what is true or what to do. It is not a summary of findings.
  5. Check the chain: Answer ← strongest hypothesis ← evidence that survived. If a link needs new facts that are not in the register, flag it.

Prompt for Copilot

You do Step A5 (Question and Answer) of a Minto analysis.

Situation: [PASTE]  Complication: [PASTE]
Strongest hypothesis + evidence: [PASTE from A3]

Do this:
1. Write THE question that the reader asks when the reader knows the
   above. One question only. The answer must set the action.
2. Check the level: is there a deeper question below the surface debate?
   If yes, give both. Recommend one.
3. Answer the question in ONE sentence. Use only the hypothesis that
   survived and its evidence.
4. Show the chain: Answer ← hypothesis ← evidence. Flag each gap.

Output: Question, Answer, chain, flags.

Your review checklist

  • ✓ One question. No "and" that connects two decisions.
  • ✓ The answer sets the action. Apply the test: "when we answer this, we know what to do".
  • ✓ It is the real question, not the surface debate.
  • ✓ The Answer follows from the A3 verdicts. You can speak the chain aloud.

GATE: one question. The answer sets the action. The chain to the evidence is complete.

Next: A6 — Write the recommendation
A6

Write the recommendation

Change the answer into an action with costs, dates, and tests

Input: Question + Answer (A5) · Output: recommendation with resources, timeline, alternatives, success metrics

Copilot procedure — do the steps in sequence

  1. Write 3 to 4 real options for the Answer. Include "do nothing" as an honest baseline with its cost. Do not make it a weak option on purpose.
  2. Score each option against five criteria: strategic fit (does it use what the evidence says we win on?), cost, time to impact, reversibility, and risk if the analysis is wrong.
  3. Select one option. Write the recommendation: what, why (one clause that points to the Answer), resources, timeline, owner.
  4. Attach success metrics: 3 to 4 measures. Each measure has a baseline, a target, and a measurement date. A metric without a date is not a metric.
  5. Attach a decision gate: the condition to stop or review. Example: "if X has not moved by [date], review before more spend". The gate makes the recommendation safe to approve.
  6. Name the key assumption: the one item that, if false, makes the recommendation invalid.

Prompt for Copilot

You do Step A6 (Recommendation) of a Minto analysis.

Question: [PASTE]  Answer: [PASTE]
Constraints: budget [X], timeline [Y], strategic context [Z]

Do this:
1. Write 3–4 real options. Include "do nothing" with its real cost.
2. Score each option: strategic fit / cost / time to impact /
   reversibility / risk if wrong. Use a short table.
3. Recommend one option. Format: what, why (point to the Answer),
   resources, timeline, owner.
4. Success metrics: 3–4. Each has a baseline, a target, and a
   measurement DATE.
5. Decision gate: the stop/review condition and its date.
6. Key assumption: the one item that, if false, makes this invalid.

Output: options table, recommendation, metrics, gate, assumption.

Your review checklist

  • ✓ The alternatives are real. You could defend each one.
  • ✓ "Do nothing" has an honest cost.
  • ✓ Each metric has a baseline, a target, and a date.
  • ✓ The decision gate makes the recommendation safe for a careful CFO.
  • ✓ The key assumption carries real load. Test: if it is false, do you still act?

GATE: the recommendation stands on evidence. It has costs, a gate, and a named assumption.

Next: A7 — Give the results to Document B
A7

Give the results to Document B

Package the analysis for the presentation workbook and the output layer

Handoff package — carry all items into Document B (step B0)

  • ✓ Problem frame (A1)
  • ✓ Situation + Complication + evidence register (A2)
  • ✓ Hypothesis table with verdicts (A3) — this is your defence material
  • ✓ Evidence sweep register (A4) — Document B carries it forward and extends it
  • ✓ Question + Answer (A5)
  • ✓ Recommendation + alternatives + metrics + gate + assumption (A6)

The recommendation becomes the Governing Thought. The registers become the material for the exhibits. The hypotheses that failed become your prepared answers to objections. They are the strongest defence asset from the analysis.

Map onto the PYRAMID DATA schema — the generators' DATA section

  • Situation + Complication (A2) → SCQA.situation / SCQA.complication
  • Question (A5) → SCQA.question
  • Recommendation (A6) → GOVERNING_THOUGHT (compress to 25 words or fewer)
  • Answer + surviving evidence (A3/A4) → KEY_LINE seeds and supports
  • Metrics + gate + key assumption (A6) → CONCLUSION + ASK
  • Actions with owners and dates (A6) → NEXT_STEPS
  • Evidence register + sweep (A2/A4) → EVIDENCE_REGISTER
